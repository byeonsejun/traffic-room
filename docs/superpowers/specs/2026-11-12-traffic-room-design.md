# 전국 도로 상황실 — 설계 문서

작성일 2026-11-12 · 상태: 검토 대기 · 폴더 이름(`traffic-room`)은 임시

## 1. 무엇을, 왜 만드나

프론트엔드 개발자 포트폴리오용 프로젝트다. 기존 프로젝트(LUMEN 3D 쇼핑몰, travel 등)에서 보여 주지 못한 세 가지 역량을 한 화면에 담는 게 목적이다.

- WebSocket · SSE 기반 실시간 이벤트 처리
- HLS(필요 시 WebRTC) 기반 브라우저 영상 재생
- 차트 라이브러리를 활용한 대시보드 · 데이터 시각화

주제는 **전국 고속도로 · 국도 실시간 관제 화면**이다. 국가교통정보센터(ITS) 공개 API로 실제 CCTV 영상, 돌발상황, 구간 속도를 받아 하나의 야간 관제 화면에 보여 준다. 사용자가 직접 고른 이유는 다음과 같다.

- 다른 프로젝트에서 못 보여 준 기능(실시간 모니터링, 지도 위 사고 위치)을 전면에 둘 수 있다.
- 프론트엔드 개발자로서 시각적 완성도를 최우선으로 보여 줄 수 있다.

주 관객은 면접관이다. 링크를 열자마자 "살아 있는 화면"이 보여야 하고, 코드와 README에서 실시간 처리를 직접 설계했다는 게 드러나야 한다.

## 2. 목표 · 비목표 · 실패 조건

**목표**
- 첫 화면에서 실제 데이터로 움직이는 관제 화면을 보여 준다.
- 새 돌발상황이 WebSocket으로 도착하는 순간을 눈에 띄게 연출한다.
- 사고 지점을 누르면 가까운 실제 CCTV 생방송이 바로 재생된다.
- CCTV를 크게 볼 수 있는 전체화면 버튼을 둔다(사용자 요청).
- 비용 0원으로 운영한다(사용자 요구: 돈을 들이지 않는다).

**비목표**
- 시내 도로 관제(ITS CCTV는 고속도로 · 국도만 제공).
- 회원가입, 로그인, 사용자별 설정.
- 모바일 우선 설계. 모바일에서 깨지지 않을 정도만 챙기고, 기준 화면은 데스크톱이다.
- 진짜 초 단위 실시간. API 한도 때문에 불가능하며, 그렇다고 숨기지도 않는다.

**실패 조건 (동작은 해도 실패로 본다)**
- 흔한 관리자 대시보드 템플릿처럼 보이는 것.
- 가짜 데이터를 실제인 척 보여 주는 것. 지연이나 재생은 화면에 솔직하게 표시한다.
- 면접관이 링크를 열었을 때 하얀 화면이나 긴 로딩만 보이는 것.
- API 한도를 넘겨 월 중간에 데이터가 끊기는 것.
- 유료 결제 수단을 연결해야만 돌아가는 구성.

## 3. 확인된 제약 (2026-11-11 실제 키로 검증)

**ITS API**
- 엔드포인트: `https://openapi.its.go.kr:9443/{cctvInfo|eventInfo|trafficInfo|...}`. 비표준 포트 9443을 쓴다.
- 인증키는 계정당 1개다. 현재 교통소통 · 돌발상황 · CCTV · 교통예측이 승인돼 있다.
- **한도는 서비스별로 월 1,000건씩**이다(마이페이지에서 서비스별 집계 확인). 파라미터 오류로 실패한 호출은 집계되지 않았다.
- 로컬 키 위치: `~/.its-api.env` (`ITS_API_KEY`, 권한 600). 저장소에는 절대 넣지 않는다.
- 공개 테스트 키 `apiKey=test`는 2020년 고정 샘플만 주고, 영상 주소도 만료돼 있어 검증에 못 쓴다.

**CCTV (`cctvInfo`)**
- `cctvType=4` → HTTPS HLS 주소. 수도권 일부 영역만 조회해도 172대가 나왔다.
- 주소(`cctvsec.ktict.co.kr/...`)는 302로 리다이렉트되며, 이때 120분짜리 서명(`wmsAuthSign`, validminutes=120)이 붙은 m3u8을 받는다.
- 재생목록 · chunklist · 세그먼트 모든 단계에 `Access-Control-Allow-Origin: *`가 있다. H.264 720×480 30fps, 3초 세그먼트다. **hls.js로 브라우저에서 직접 재생 가능하고 서버 중계는 필요 없다**(시안에서 실제 재생 확인).
- 호출할 때마다 주소가 새로 나오지만, 예전 주소도 계속 유효하다. 발급 후 **최소 8시간** 유효함을 확인했다(10분~480분 사이 7회 측정, 모두 302 정상). 그 이후는 측정하지 않았다.

**돌발상황 (`eventInfo`)**
- `type=all&eventType=all` 한 번 호출로 전국이 다 온다. 확인 당시 284건이었다.
- 유형 분포: 공사 252, 기타 14, 기타돌발 9, 교통사고 7, 재난 2.
- 필드: type, eventType, eventDetailType, startDate, endDate, coordX/Y, roadName, roadNo, roadDrcType, lanesBlocked, message, linkId.
- 주의: "교통사고" 분류에 시민 신고 포트홀 같은 항목이 섞여 있다. 화면용 분류는 따로 다시 매핑해야 한다.

**교통소통 (`trafficInfo`)**
- 영역으로 조회하려면 `type=all&drcType=all`과 bbox가 필요하다. 수도권 일부만 조회해도 구간 7,490개, 응답 1.5MB였다.
- createdDate가 정각(23:00:00)으로 찍혀 있다. 정확한 갱신 주기는 아직 모른다.
- 필드: linkId, roadName, speed, travelTime, createdDate. **구간 좌표는 없다**(linkId → 표준노드링크 데이터로 좌표를 얻어야 함).

**비용 · 호스팅**
- Vercel Hobby: 프론트 무료(비상업).
- Render 무료 웹 서비스: 15분 동안 요청이 없으면 잠들고, 깨어나는 데 약 1분 걸린다. 2026-02부터는 WebSocket 메시지가 오가는 동안 잠들지 않는다. 월 750시간.
- Neon 무료 Postgres: 데이터 저장.
- 지도: MapLibre + OpenFreeMap. 키와 사용량 제한이 없다. `styles/dark`가 있지만 upstream이 관리를 중단한 스타일이므로, 직접 손본 스타일 JSON을 쓴다.
- 카카오맵은 2026-07 정책 변경으로 쓰지 않는다.

## 4. 고려한 방식과 선택

1. **프론트(Vercel)와 실시간 서버(Render) 분리 — 선택함.** 서버가 잠들어 있어도 화면은 바로 뜨고 "연결 중" 상태부터 보여 줄 수 있다. WebSocket · SSE 서버를 직접 짠 코드가 남는다. 대신 배포할 곳이 둘이고 CORS · 주소 설정을 따로 해야 한다.
2. Render 서버 하나로 전부 올리기. 배포는 가장 단순하지만, 서버가 잠들면 화면 전체가 1분간 하얗게 떠서 첫인상 실패 조건에 걸린다.
3. 실시간 기능을 외부 서비스(Supabase Realtime 등)에 맡기기. 코드는 가장 적지만 "WebSocket · SSE를 직접 다뤘다"는 프로젝트 목적과 어긋난다.

프론트 프레임워크는 사용자가 **Next.js**로 정했다. 기존 프로젝트와 같은 스택이다.

## 5. 사용자가 정한 것

- 주제: 전국 고속도로 · 국도 관제(ITS 데이터로 통일, 업비트 같은 무관한 데이터는 넣지 않음).
- 시각 방향: **시안 C "야간 속도 지도"** 발전형(시안 파일: `docs/design/direction-c-mockup.html`, 비교했던 A·B·C 시안: `docs/design/visual-directions-abc.html`).
  - 어두운 지도 위에 도로를 속도별 색(원활 · 서행 · 정체)으로 빛나게 그린다.
  - **도로 위 빛이 흐르는 속도 = 실제 통행 속도**. 이 화면의 시그니처다.
  - 돌발상황 지점에서 파동이 퍼진다. 새로 도착하면 더 큰 파동, 피드 카드 등장, 카운터 증가, 연결 표시 깜빡임이 한 번에 일어난다.
  - 레이아웃: 상단 바(이름 · 연결 상태 · 시계) / 왼쪽 지표(평균 속도, 원활 · 서행 · 정체 비율, 진행 중 돌발 수, 유형별 막대) / 가운데 지도 / 오른쪽 CCTV + 실시간 피드 / 하단 24시간 타임라인.
- CCTV 전체화면 버튼.
- 실시간 서버 분리 구조(4장 1번), Next.js.
- 비용 0원. 결제 수단을 연결하는 서비스는 쓰지 않는다(Oracle Cloud 제외 이유).

## 6. 구조

```
[GitHub Actions 매시 정각+5분]                     [Vercel: Next.js]
  수집기 ── ITS API(돌발·소통·CCTV) ──▶ Neon ◀── 초기 스냅샷 REST
                                         │                 ▲
                                         ▼                 │ WebSocket / SSE
                               [Render: Node 실시간 서버] ──┘
                               - 새 스냅샷 감지 → 이전과 비교
                               - 지연 재생 스케줄러
                               - 접속자에게 이벤트 푸시
       [cron-job.org 10분마다 ping] ──▶ Render (잠들지 않게)
```

**수집과 실시간 서버를 나눈 이유 (내 판단):** Render 무료 서버는 잠들거나 재시작될 수 있다. 수집을 서버 안에서 하면 그동안 데이터가 빈다. 수집은 GitHub Actions 스케줄(무료, 공개 저장소)이 맡아 Neon에 쌓고, 실시간 서버는 Neon에서 읽어 내보내기만 한다. 서버가 잠들었다 깨어나도 데이터는 이어진다. Actions 스케줄은 몇 분씩 늦어질 수 있지만 1시간 주기에는 문제없다.

**알려진 함정:** 공개 저장소에 60일 동안 활동이 없으면 GitHub가 스케줄 워크플로를 자동으로 끈다. 수집 결과 요약을 저장소에 커밋하지는 않는다(이력이 지저분해진다). 대신 cron-job.org가 Render ping과 함께 `workflow_dispatch`를 주기적으로 호출하는 방법이나 keepalive 액션 중 하나로 막는다(내 판단, 빌더가 최종 선택).

**API 호출 예산 (서비스별 월 1,000건)**
| 서비스 | 주기 | 월 사용량 |
|---|---|---|
| 돌발상황 | 매시 1회(전국) | 약 744 |
| 교통소통 | 매시 1회(관심 영역) | 약 744 |
| CCTV 목록 | 하루 3회(8시간마다, 주소 유효 시간 실측 기준) | 약 93 |
| 교통예측 | 하루 몇 회(선택) | 100 이하 |

개발 중에는 실제 API를 부르지 않는다. 2026-11-11에 받은 실제 응답을 `fixtures/`에 저장해 재생하는 모드를 기본값으로 둔다. 실제 호출은 배포된 수집기만 한다.

## 7. 실시간 처리

**지연 재생 (사용자 동의):** 매시 수집된 돌발상황을 이전 스냅샷과 비교한다.
- 새로 생긴 상황은 실제 `startDate` 간격을 지켜서 **약 1시간 늦게 하나씩** 내보낸다.
- 사라진 상황(종료)도 같은 방식으로 "해제" 이벤트를 보낸다.
- 화면에는 "약 1시간 지연"이라고 늘 표시한다. 가짜 이벤트는 만들지 않는다.
- 공사처럼 오래 이어지는 상황은 처음 받은 스냅샷에 "진행 중"으로만 들어가고, 도착 연출은 하지 않는다.
- **서버가 재시작돼도 어긋나지 않게(내 판단):** 각 이벤트의 송출 시각은 `startDate + 1시간`처럼 데이터에서 계산되는 값이고, Neon에 저장한다. 스케줄러는 메모리 상태 없이 "지금 송출할 차례인 이벤트"를 DB에서 다시 계산한다. 그래서 잠들었다 깨어나도 이어서 내보낸다. 모든 접속자는 같은 순간에 같은 이벤트를 받는다(브로드캐스트).
- 원본에 `startDate`가 비어 있거나 `0000`처럼 비정상인 항목(시민 신고 일부)은 수집 시각을 기준으로 삼는다.

**WebSocket과 SSE의 역할 (내 판단, 둘 다 보여 주기 위해 성격을 나눔)**
- **WebSocket (양방향):** 돌발상황 도착 · 해제 이벤트, 클라이언트가 보고 있는 지도 영역 구독, CCTV 선택 요청과 응답. 하트비트, 재연결(지수 백오프), 재연결 시 놓친 이벤트를 따라잡는 처리(마지막 이벤트 id 기준)를 직접 구현한다.
- **SSE (단방향):** 지표 스트림(평균 속도, 비율, 다음 수집까지 남은 시간, 서버 상태). 브라우저 기본 재연결과 `Last-Event-ID`를 활용한다.
- 메시지는 공통 봉투 `{ id, type, ts, payload }`로 통일하고, 타입은 zod로 서버 · 클라이언트가 함께 검증한다.

**연결 상태 UI:** 연결 중(서버 깨우는 중) → 연결됨 → 끊김 · 재시도 중. 서버가 잠들어 있으면 첫 1분 동안 Neon 스냅샷(REST)으로 화면을 먼저 채우고, 연결되면 실시간으로 넘어간다.

## 8. 화면 세부

- **지도:** MapLibre GL + OpenFreeMap 벡터 타일, 직접 손본 어두운 스타일.
  - 도로 구간은 속도 색 선과, 그 위를 흐르는 점선 애니메이션 두 겹으로 그린다. 흐름 속도는 실제 속도에 비례한다.
  - 교통소통에는 좌표가 없으므로 ITS 표준노드링크 파일로 linkId → 좌표를 미리 만들어 둔다. 고속도로 링크만 걸러 정적 GeoJSON으로 빌드한다.
- **돌발 마커:** 유형별 색(정체 · 사고 빨강, 고장 · 낙하물 노랑, 기상 · 재난 파랑, 공사는 회색으로 낮춤). 진행 중이면 잔잔한 파동, 새로 도착하면 큰 파동 3회.
- **CCTV 패널:** hls.js 재생과 근처 CCTV 전환 칩.
  - **전체화면 버튼:** Fullscreen API로 영상을 크게 보고, Esc로 닫는다. 미지원 브라우저에서는 화면을 꽉 채우는 오버레이로 대체한다.
  - 주소가 만료돼 재생에 실패하면 서버에 새 주소를 한 번 요청하고, 그래도 실패하면 상황을 설명하는 안내를 보여 준다.
- **실시간 피드:** 최근 순, 새 카드는 위에서 밀려 들어온다. 카드를 누르면 지도가 그 지점으로 이동하고 CCTV가 바뀐다.
- **왼쪽 지표:** 차트 라이브러리는 빌더가 고른다(아래 참고). 평균 속도 큰 숫자, 비율 막대, 유형별 막대, 1시간 추이.
- **24시간 타임라인:** Neon에 쌓인 실제 이력으로 그린다. 끌어서 과거를 재생하는 기능은 2차로 미룬다.
- **디자인 토큰 (시안 기준):** 배경 #0C131D, 패널 #111B28, 선 #1D2A3A, 글자 #DCE4EE, 보조 #7C8A9B, 원활 #2BD47D, 서행 #F5B83D, 정체 #FF4D4F, 정보 #5AA9FF. 글꼴 IBM Plex Sans KR(숫자는 tabular-nums).
- **품질 바닥선:** 키보드 포커스 표시, `prefers-reduced-motion`에서 흐름 · 파동 애니메이션 중지, 1100px 이하에서는 세로 배치.

## 9. 범위 나누기

- **1차:** 지도 + 돌발 마커 + WebSocket 지연 재생 + 피드 + CCTV 재생 · 전체화면 + 연결 상태 + 수집기 + 배포.
- **2차:** 교통소통 속도 도로선 · 흐름 애니메이션 + SSE 지표 + 왼쪽 차트.
- **3차:** 24시간 타임라인 + 과거 재생, 교통예측 대 실제 비교 차트, 선택 사항으로 WebRTC(예: 선택한 CCTV를 다른 사용자와 같이 보기).

WebRTC는 공개 API로 받을 영상이 없어서 3차 선택 사항으로 둔다. HLS만으로 "브라우저 영상 재생" 요구는 채워진다.

## 10. 빌더에게 맡기는 것

- 차트 라이브러리 선택. ECharts(캔버스, 다크 테마 · 애니메이션에 강함)를 우선 검토하고, 근거를 남긴다. dataviz 스킬 기준을 따른다.
- 상태 관리. 기존 프로젝트처럼 zustand가 기본값이다.
- 모노레포 구성(예: pnpm workspace로 `apps/web`, `apps/realtime`, `packages/shared`, `scripts/collector`).
- Neon 스키마 세부(스냅샷 원본 저장 범위, 보관 기간, 용량 0.5GB 안에서 정리하는 방법).
- 교통소통 조회 영역(전국 vs 수도권 등). 응답 크기와 표준노드링크 매핑 비용을 보고 정한다.
- 테스트 범위. 비교(diff) · 지연 재생 스케줄러 · 메시지 검증은 단위 테스트를 필수로 한다.
