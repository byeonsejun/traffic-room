# 전국 도로 상황실 2차 — 설계 문서

작성일 2026-11-13 · 상태: 검토 대기 · 1차 설계: `2026-11-12-traffic-room-design.md`

## 1. 무엇을, 왜

1차는 돌발상황 지도, WebSocket 지연 재생, CCTV 재생까지 만들어 운영 중이다. 2차는 처음 기획에서 미뤄 둔 두 가지를 채운다.

- **도로 속도선:** 어두운 지도 위에 고속도로를 속도 색(원활·서행·정체)으로 빛나게 그리고, 그 위를 흐르는 빛의 빠르기가 실제 통행 속도를 따르게 한다. 시안 C "야간 속도 지도"의 시그니처다.
- **차트 대시보드:** 차트 라이브러리로 만든 전문적인 대시보드와 데이터 시각화. 관제 화면 왼쪽에는 핵심 지표를, 별도 분석 페이지(`/insights`)에는 깊은 분석을 둔다.

사용자의 말로 정리하면 이렇다. "우리에게 필요한 건 실시간처럼 보이는 화면이다." 그리고 "프론트엔드 개발자라 시각적으로 뛰어난 포트폴리오를 보여 주는 게 중요하다." 주 관객은 1차와 같이 면접관이다.

## 2. 목표 · 비목표 · 실패 조건

**목표**
- 관제 지도에 고속도로 본선을 속도 색으로 그리고, 속도 단계에 따라 빛이 다른 빠르기로 흐르게 한다.
- 관제 화면 왼쪽에 평균 속도(큰 숫자 + 24시간 추이), 구간 상태 비율, 돌발 지표를 보여 준다.
- `/insights` 분석 페이지에 지표 타일 4개, 노선 × 시간 속도 히트맵, 느린 노선 순위, 구간 상태 비율 추이, 시간대별 돌발 발생 차트를 둔다.
- 두 화면이 SSE 지표 스트림으로 함께 움직인다.
- 데이터는 쌓지 않고 덮어쓴다. 새 데이터는 검증을 통과했을 때만 화면에 쓰인다.
- 지도를 한국 범위로 묶는다.
- 비용 0원을 유지한다.

**비목표**
- 국도 · 시내 도로 속도선. 고속도로만 그린다(사용자 결정).
- 과거 재생 · 24시간 타임라인 스크럽, 교통예측 비교(3차).
- 구간마다 정확히 다른 속도로 흐르는 입자 애니메이션(deck.gl). 속도 단계별 흐름으로 충분한지 먼저 본다.
- 모바일 최적화. 데스크톱 기준이고, 모바일은 세로로 쌓여 깨지지 않을 정도만 챙긴다.

**실패 조건 (동작해도 실패로 본다)**
- 흔한 관리자 대시보드 템플릿처럼 보이는 것.
- 지어낸 값으로 차트나 도로 색을 채우는 것. 빈 기록 · 오래된 데이터 · 데이터 없는 구간은 화면에 솔직하게 표시한다.
- 검증되지 않은 데이터(빈 응답, 일부만 온 응답)가 화면에 나가는 것.
- DB가 계속 커지는 것(Neon 무료 0.5GB).
- 첫 화면이 눈에 띄게 느려지는 것. 도로 모양 · 차트 라이브러리 때문에 지도와 돌발이 늦게 뜨면 안 된다.

## 3. 확인된 사실 (2026-11-13 실측)

**교통소통 (`trafficInfo`)**
- 고속도로만 요청(`type=ex`)하려면 노선 번호(`routeNo`)가 필수라 노선마다 따로 불러야 한다. 64노선 × 매 수집이면 한도를 넘는다. 그래서 `type=all&drcType=all` + 한국 전역 bbox(124~132, 33~39)로 **한 번에 전국**을 받는다.
- 전국 응답: **383,618구간, 75MB, 19초.** 시내 도로까지 다 들어 있다.
- 응답 안의 `createdDate`는 모두 같은 값이다(한 시점의 스냅샷). 11:10에 부르면 `11:00:00`, 11:50에 부르면 `11:45:00`이었다. **원천 데이터는 최소 15분마다 갱신된다.**
- 고속도로는 `roadName`에 "고속도로"가 들어 있다(64노선, 14,861구간). 돌발상황의 노선 이름("경부선")과 표기가 다르다.
- 측정에 교통소통 2건을 썼다(이번 달).

**표준노드링크 (2026-11-11 기준, 사용자가 ITS 자료실에서 받음)**
- `~/Downloads/[2026-11-11]NODELINKDATA.zip` (260MB, 풀면 845MB). `MOCT_LINK.shp/.dbf/.shx/.prj`가 필요한 파일이다. 저장소에는 넣지 않는다.
- 링크 1,576,531개. 필드: `LINK_ID`, `ROAD_RANK`(101 = 고속국도), `ROAD_NAME`, `CONNECT`(0 본선, 1 연결로), `LENGTH`(m), `LANES`, `MAX_SPD` 등. 문자열은 CP949.
- 좌표계: TM 중부원점 계열(GRS80, 중앙자오선 127°, 원점 위도 38°, 가산 200,000 / 600,000, 축척 1.0). 직접 역변환해 경위도로 바꿨고, 실제 지도의 고속도로와 정확히 겹치는 것을 확인했다.
- 교통소통 고속도로 14,861구간 중 **14,202구간(95.6%)이 노드링크와 이어진다.** 빠진 659구간(경부 162, 수도권제2순환 90 등)은 번호가 바뀐 구간으로 보인다.
- 연결로(`CONNECT=1`) 5,238구간은 평균 56km/h로, 본선이 원활해도 정체처럼 보이게 만든다. **본선(`CONNECT=0`) 8,964구간**만 쓰면 깔끔하다(평균 90km/h).
- 본선 8,964구간 도로 모양: 8m 허용 오차로 점을 줄이고(20만 → 4.8만), 좌표를 소수 4자리로 두면 약 1.2MB, gzip 약 190KB.
- 데이터가 아예 없는 고속도로 본선 구간이 있어, 속도 색만 그리면 선이 점선처럼 끊겨 보인다.
- 이용 조건: 무료, 이용 범위 제한 없음(공공데이터포털 15025526).

**호출 한도**
- 서비스별 월 1,000건. 사용자가 운영용 한도 상향을 신청했다(2026-11-13, 관리자 승인 대기). 승인 여부와 시기는 모른다.

## 4. 고려한 방식과 선택

**화면 배치 (사용자 선택: C)**
- A. 관제 화면 왼쪽에 다 넣기. 첫인상은 강하지만 패널 폭(약 250px) 때문에 차트가 작고 3~4개가 한계다.
- B. 별도 분석 페이지만. 차트를 크게 보여 줄 수 있지만 첫 화면에 차트가 없다.
- **C. 둘 다.** 관제 화면에는 핵심 지표, `/insights`에 깊은 분석. 같은 SSE 스트림을 받는다. 작업량이 가장 크다. 목업: `.superpowers/brainstorm/…/content/dashboard-options.html`(로컬).

**만드는 방법 (사용자 선택: 1)**
1. **ECharts + MapLibre 레이어.** 차트는 ECharts(캔버스, 히트맵 · 면 · 막대 · 툴팁 · 전환 애니메이션 내장, 필요한 차트만 import). 흐름은 지금 쓰는 MapLibre 선 레이어로 만들고, 속도를 단계로 나눠 단계별로 흐름 빠르기를 다르게 한다. 새 지도 라이브러리가 없다.
2. visx(D3) + MapLibre. 모양을 완전히 직접 만들 수 있지만 툴팁 · 전환 · 히트맵을 다 짜야 하고 SVG라 셀이 많으면 무겁다.
3. ECharts + deck.gl TripsLayer. 구간마다 정확한 속도로 입자가 흐르지만 번들 수백 KB 증가, MapLibre와 겹치는 설정, GPU 부담, 빌드 위험이 생긴다.

**저장 방식 (사용자 제안: 덮어쓰기)**
- 시간마다 전체를 쌓으면 고속도로만이어도 하루 수십 MB씩 늘어난다. 최신 스냅샷만 두고 지난 것은 지우는 덮어쓰기를 쓴다. 차트에 필요한 과거는 작은 요약 표로만 남긴다.

## 5. 사용자가 정한 것

- 목표는 "실시간처럼 보이는 화면". 화려한 시각화가 포트폴리오의 핵심.
- 속도선은 고속도로만.
- 데이터는 쌓지 않고 덮어쓰며, 필요 없는 데이터는 지운다.
- 데이터가 제대로 안 오거나 연결이 끊기는 상황에 대비한 안전장치. 새 데이터는 검증됐을 때만 바꾸고, 이전 데이터를 남겨 둔다.
- 지도는 한국만 보이게.
- 화면 배치 C, 기술 방식 1(ECharts + MapLibre).
- 표준노드링크는 사용자가 직접 한 번 받아 둔다.
- 월 호출 한도 상향 신청(승인 대기).

## 7. 데이터

### 7.1 도로 모양 (한 번만 만드는 정적 파일)

- `scripts/build-highways.mjs`(새로): 노드링크 zip 경로를 인자로 받아 `MOCT_LINK`를 읽고, `ROAD_RANK=101` 이고 `CONNECT=0`인 **고속도로 본선 전체**를 뽑는다. 데이터 유무와 관계없이 본선 전체를 넣는다(아래 "바탕선"에 씀).
- SHP · DBF는 의존성 없이 직접 읽는다(형식이 단순하고, 확인 단계에서 표준 라이브러리만으로 읽었다). TM → 경위도 역변환, 더글러스-포커 단순화(약 8m), 좌표 소수 4자리.
- 출력 `apps/web/public/highways.json`: 구간마다 `linkId`, `route`(노선 이름, CP949 → UTF-8), 길이(m), 좌표. 목표 크기 gzip 500KB 이하. 넘으면 단순화 허용 오차를 키운다.
- 노선 목록 `packages/shared`에 둔다: 노드링크의 `ROAD_NAME`과 교통소통의 `roadName`을 같은 노선으로 묶는 표. 히트맵과 노선 순위가 이 이름을 쓴다.
- 이 스크립트와 결과 파일은 노드링크가 갱신돼 다시 받을 때만 다시 돌린다. 수집기는 "도로 모양에 없는 고속도로 구간 수"를 기록해 두어, 그 수가 커지면 다시 받을 때가 된 것을 알 수 있게 한다.

### 7.2 수집 (`traffic` 작업, Mac)

- `apps/collector/src/run-traffic.ts`(새로). 1차 `run-events.ts`와 같은 모양: 예산 확인 → 호출 → 거르기 → 검증 → 저장 → 실행 기록.
- `packages/its`에 `traffic()`을 더한다. 전국 bbox로 한 번 부르고, 응답을 **스트리밍으로 읽으며** 도로 모양에 있는 본선 `linkId`만 남긴다(75MB를 통째로 메모리에 올리지 않기 위해서다. 빌더가 측정해서 통째로 읽어도 괜찮으면 단순한 쪽을 택해도 된다).
- 어떤 `linkId`를 남길지는 `apps/web/public/highways.json`의 구간 목록으로 정한다. 수집 전용 복사본도 같은 저장소라 `git pull`로 함께 갱신된다. 정체 길이(`jam_km`)는 이 파일의 구간 길이로 계산한다.
- 수집 주기는 설정값이다(7.6).
- `collector_runs.service`에 `'traffic'`을 더한다(스키마 check 제약 수정).

### 7.3 저장 (덮어쓰기)

```
traffic_snapshots
  id bigserial pk
  data_at timestamptz       -- 응답의 createdDate (원천 데이터 시각)
  collected_at timestamptz
  show_at timestamptz       -- data_at + 지연. 이 시각부터 화면에 나간다
  link_count int
  avg_speed real, ok int, slow int, jam int, jam_km real   -- 요약을 미리 계산해 둔다
  status text  -- 'writing' | 'ready' | 'rejected'

link_speeds
  snapshot_id bigint references traffic_snapshots on delete cascade
  link_id text
  speed smallint
  primary key (snapshot_id, link_id)

traffic_buckets      -- 24시간 추이용. 수집 한 번에 한 줄
  data_at timestamptz pk, avg_speed, ok, slow, jam, jam_km

route_buckets        -- 히트맵 · 노선 순위용
  data_at timestamptz, route text, avg_speed real, primary key (data_at, route)
```

- **쓰기 순서:** 새 스냅샷을 `status='writing'`으로 만들고 `link_speeds`를 넣는다 → 검증(7.4) → 통과하면 한 트랜잭션 안에서 `status='ready'`로 바꾸고 `traffic_buckets` · `route_buckets`에 한 줄씩 넣는다 → 실패하면 `rejected`로 표시하고 그 행들을 지운다.
- **화면이 쓰는 스냅샷:** `status='ready'`이고 `show_at <= now` 중 가장 최근 것. 다음 것(`show_at > now`)이 대기 중일 수 있다.
- **덮어쓰기:** 새 스냅샷이 `ready`가 되면 `ready` 중 최신 3개(대기 중 · 지금 보여 주는 것 · 바로 전 것)만 남기고 나머지를 지운다. "바로 전 것"을 하나 더 남기는 이유는, 지금 보여 주는 스냅샷에 문제가 드러났을 때 되돌릴 곳을 두기 위해서다(사용자 요청: 이전 데이터를 한 번 남겨 두기). 고속도로 본선 9천 행 × 3 = 약 2만 7천 행, 약 2MB.
- **요약 표:** `traffic_buckets` · `route_buckets`는 `data_at`이 26시간보다 오래된 줄을 지운다. 차트는 최근 24시간만 그리고, 남는 2시간은 "어제 같은 시각" 비교에 쓴다. 15분 간격이면 약 104줄 · 104 × 노선 수.
- **1차 표 정리(새로):** 해제된 지 7일이 지난 `incidents`와 그 `event_log`, 30일이 지난 `collector_runs`를 지운다. 수집이 성공한 뒤에 한다. 재접속 따라잡기는 최대 200건이고 끊긴 지 오래면 스냅샷을 다시 받으므로, 7일 전 송출 기록이 없어도 된다.

### 7.4 검증과 안전장치

새 스냅샷은 아래를 모두 통과해야 `ready`가 된다.
- 응답 `resultCode = 0`이고 JSON이 끝까지 읽혔다.
- 남은 본선 구간 수가 직전 `ready` 스냅샷의 80% 이상이다. 직전이 없으면 도로 모양 구간 수의 50% 이상이다.
- 속도가 0~200km/h이고, 0인 구간이 전체의 5% 미만이다.
- `createdDate`가 하나의 값이고, 직전 `ready`보다 새것이다. 같으면 새로 쓰지 않고 실행만 기록한다(원천이 아직 안 바뀐 경우).

실패하면 이전 스냅샷이 그대로 화면에 남는다. 실패 사유는 `collector_runs`와 로그 한 줄에 남긴다(키 · 접속 문자열 미출력, 1차 규칙 그대로).

화면 쪽 안전장치:
- SSE · WebSocket이 끊기거나 새 스냅샷이 오지 않으면, 마지막으로 받은 도로 색과 지표를 유지한다.
- 상단에 `교통 HH:mm 기준`을 표시한다. 그 시각이 지금 − 지연 − 2 × 수집 간격보다 오래되면 1차의 "수집 일시 중지"처럼 노란색으로 바꾼다.
- `/api/traffic`이 실패하면 속도선 없이 바탕선만 보이고, 범례에 "교통 정보를 불러오지 못했어요"를 띄운다. 돌발 · CCTV는 영향받지 않는다.

### 7.5 지연 맞추기

속도도 돌발처럼 지연해서 보여 준다. 돌발은 1시간 늦게 도착하는데 도로 색만 지금 것이면, 정체가 먼저 보이고 그 원인인 사고가 한참 뒤에 도착하는 어긋남이 생긴다. `show_at = data_at + 지연`으로 둘을 맞춘다.

### 7.6 설정값 (한도 상향 승인 대비)

지금은 하드코딩된 값들을 설정으로 뺀다. 승인 전에는 지금 값 그대로 돌고, 승인되면 숫자만 바꾼다.

| 이름 | 지금 | 승인 후 예시 | 쓰는 곳 |
|---|---|---|---|
| 수집 간격(분) | 60 | 15 | launchd 일정, 수집 스크립트의 "직전 성공 N분 안이면 건너뜀" |
| 지연(분) | 60 | 20 | 수집기 송출 시각 계산, `show_at`, 화면 문구 "약 N분 지연" |
| 월 한도(서비스별) | 950 | 2,900 | `canCall` |

- 화면의 "약 1시간 지연"은 `/api/snapshot`이 이미 돌려주는 `delayMinutes`로 그린다(지금은 상수). 60이면 "약 1시간", 그 밖에는 "약 N분".
- 교통소통 75MB × 수집 횟수는 Mac 회선 사용량이다. 60분이면 월 약 56GB, 15분이면 약 220GB. 문서 `deploy.md`에 남긴다.

## 8. 실시간: SSE 지표 스트림

- Render 실시간 서버에 `GET /sse/metrics`를 더한다. CORS는 1차의 `ALLOWED_ORIGINS`를 쓴다.
- 이벤트 종류:
  - `metrics`: 지금 지표 전체 한 덩어리. 평균 속도, 원활 · 서행 · 정체 구간 수, 정체 길이, 진행 중 돌발 수와 유형별 수, 지금 보여 주는 교통 스냅샷 `id` · `data_at`, 다음 교통 갱신 시각, 지연(분).
  - 서버가 보낼 때마다 `id`를 하나씩 올린다. 상태 스트림이라 재접속하면 `Last-Event-ID`와 상관없이 지금 상태 전체를 먼저 보낸다. 브라우저 기본 재연결을 쓴다.
  - 25초마다 주석 줄(`: ping`)로 연결을 유지한다.
- 언제 보내나:
  - 접속 직후 한 번.
  - 돌발이 도착 · 해제될 때(1차 스케줄러의 송출에 맞춰 진행 중 돌발 수만 바꿔서).
  - 대기 중인 교통 스냅샷의 `show_at`이 될 때(속도 지표가 바뀌고, 브라우저는 `/api/traffic`을 다시 받는다).
- DB 읽기는 1차와 같이 30분에 한 번만 한다(Neon 자동 일시정지 유지). 다음 30분 안에 `show_at`이 되는 스냅샷의 요약값(7.3에서 미리 계산해 둔 열)도 그때 함께 읽어 두었다가 시각에 맞춰 보낸다.
- 역할 나누기: WebSocket은 이벤트 하나하나(도착 · 해제 · CCTV 요청, 양방향), SSE는 화면 전체가 공유하는 지표 상태(단방향). 1차 설계 7장의 나누기 그대로다.

## 9. 화면

### 9.1 관제 지도

- **한국으로 묶기:** `maxBounds`(대략 경도 123.5~132.5, 위도 32.5~39.3), `minZoom`(전국이 꽉 차는 정도), `renderWorldCopies: false`.
- **바탕선:** `highways.json`의 본선 전체를 어두운 회색 선으로 깐다. 데이터 없는 구간도 끊겨 보이지 않는다.
- **속도선:** 데이터가 있는 구간을 속도 색으로 덮는다. 원활(≥70km/h) `#2BD47D`, 서행(40~70) `#F5B83D`, 정체(<40) `#FF4D4F`. 1차 디자인 토큰과 같다. 빛 번짐 한 겹 + 선 한 겹.
- **흐름:** 속도를 5단계쯤으로 나누고, 단계마다 점선이 흐르는 레이어를 따로 둔다. 빠른 단계일수록 빨리 흐르고, 정체는 거의 멈춘다. 단계 경계와 빠르기는 빌더가 화면을 보며 정한다.
- **확대 단계별 두께:** 전국 보기에서는 선이 점처럼 보이지 않게 두께 · 번짐을 확대 정도에 따라 보간한다.
- `prefers-reduced-motion`이면 흐름을 멈추고 색만 보인다(1차 원칙).
- 돌발 마커와 파동은 속도선 위에 그린다.
- 매 교통 갱신 때 색이 한꺼번에 튀지 않게, 몇 초에 걸쳐 바뀌게 한다(보간 값을 지어내지 않고 표시 전환만).
- 범례: 원활 · 서행 · 정체 · 데이터 없음, 그리고 `교통 HH:mm 기준`.

### 9.2 관제 왼쪽 패널

위에서부터:
1. 고속도로 평균 속도 큰 숫자 + 24시간 추이 선(ECharts 작은 선 차트, 툴팁).
2. 구간 상태: 원활 · 서행 · 정체 구간 수 비율 막대, 숫자 라벨.
3. 진행 중 돌발 수 + 유형별 막대(1차 것 유지).
4. "분석 보기 →" 링크(`/insights`).
5. 1차의 안내 문구(지연 · 마지막 수집).

### 9.3 분석 페이지 `/insights`

- 상단 바는 관제와 같고, "관제 · 분석" 탭을 둔다.
- 지표 타일 4개: 평균 속도(어제 같은 시각과 비교는 24시간 기록이 찬 뒤에만), 정체 구간 길이(km), 진행 중 돌발(사고 · 고장 수), 다음 교통 갱신까지 남은 시간.
- **노선 × 시간 평균 속도 히트맵:** 최근 24시간, 주요 노선(본선 길이 기준 상위 12개쯤, 빌더가 정함). 순차 색상 한 계열(느림 → 빠름), 셀 툴팁.
- **지금 느린 노선 순위:** 노선별 평균 속도 하위 7개, 막대 + 속도 라벨.
- **구간 상태 비율 추이:** 24시간 원활 · 서행 · 정체 누적 면 차트, 십자선 툴팁.
- **시간대별 돌발 발생:** 최근 24시간 `incidents.started_at`을 1시간 단위로 센 막대. 막대에 마우스를 올리면 그 시간의 상황 수 · 유형.
- 데이터는 `/api/insights`(Vercel, `s-maxage` 60초)로 처음 받고, SSE `metrics`가 오면 타일을 바꾸고, 교통 스냅샷이 바뀌면 `/api/insights`를 다시 받는다.
- **빈 기록:** 교통소통은 과거를 주지 않아서 배포 직후 24시간은 기록이 차 오르는 중이다. 차트는 있는 만큼만 그리고 "기록 중 · 9/24시간"을 표시한다. 빈 칸을 지어내지 않는다.
- 차트 규칙: 하나의 y축만, 상태 색(원활 · 서행 · 정체)은 라벨과 함께, 2개 이상 계열에는 범례, 텍스트는 글자색 토큰(계열 색 아님), 다크 배경 기준으로 대비 확인. 각 차트에 표로 보기(접근성)를 둔다.
- ECharts는 필요한 차트 · 컴포넌트만 import하고 `/insights`와 관제 왼쪽 패널에서만 동적으로 불러온다. 지도 · 돌발 첫 화면이 차트 때문에 늦지 않게 한다.

## 10. API 정리

| 경로 | 위치 | 내용 | 캐시 |
|---|---|---|---|
| `/api/snapshot` | Vercel | 1차 그대로 + `delayMinutes` 설정값 반영 | s-maxage 60 |
| `/api/traffic` | Vercel | 지금 보여 줄 스냅샷의 `[linkId, speed]` 배열 + `id` · `data_at` · 다음 `show_at` | s-maxage 60 |
| `/api/insights` | Vercel | `traffic_buckets` · `route_buckets` 24시간 + 시간대별 돌발 수 | s-maxage 60 |
| `/sse/metrics` | Render | 8장 | 없음 |
| `/ws` | Render | 1차 그대로 | 없음 |

운영에서 DB를 못 읽으면 1차처럼 503을 돌려주고, 로컬에서 DB가 없으면 픽스처로 채운다.

## 11. 테스트와 확인

- 단위: 도로 모양 빌드(작은 SHP · DBF 픽스처로 읽기 · 역변환 · 필터), 교통소통 정규화 · 거르기, 검증 규칙 각각, 스냅샷 회전(최신 3개 유지), 요약 표 정리, 1차 표 정리, SSE 스트림(접속 직후 상태, 돌발 송출 시 갱신, `show_at` 시각 갱신, ping), 설정값 읽기.
- 화면: 속도 단계 계산, 범례 · 기준 시각 · 오래됨 표시, 빈 기록 표시, ECharts는 목으로 바꾸고 옵션 객체를 검사.
- 픽스처: 2026-11-13 실측 응답에서 고속도로 본선 일부(수도권 · 한 노선 전체 정도)만 잘라 `packages/its/fixtures/traffic.json`으로 둔다. 1MB 이하.
- 브라우저: 로컬 화면을 띄워 전국 · 확대 화면에서 속도선 · 흐름 · 바탕선을 캡처로 확인하고, `/insights`의 각 차트를 찍어 겹침 · 넘침을 본다(1차 원칙: 브라우저 확인은 직접).
- 운영: 배포 후 Mac에서 `collect-local.sh --traffic --dry-run`, 실제 한 번 실행, 운영 화면 확인.

## 12. 범위 밖 (3차 또는 나중)

- 24시간 타임라인 스크럽 · 과거 재생, 교통예측 대 실제 비교, WebRTC.
- 국도 속도선(노드링크 `ROAD_RANK`로 거를 수 있지만 데이터가 몇 배).
- 연결로(나들목 · 분기점) 표시.
- 구간마다 정확한 입자 흐름(deck.gl).
- 지도 영역 구독(WebSocket). 고속도로만 그리면 전국 데이터가 작아서(gzip 약 56KB) 필요가 줄었다.

## 13. 빌더에게 맡기는 것

- 속도 단계 경계와 단계별 흐름 빠르기, 확대 단계별 선 두께 · 번짐.
- 히트맵에 넣을 노선 수와 순서, 노선 이름 묶기 표의 세부.
- 75MB 응답을 스트리밍으로 읽을지, 통째로 읽을지(측정 후).
- ECharts 테마 세부(1차 디자인 토큰 안에서).
- 마이그레이션 방식(1차 `schema.sql`의 `create … if not exists` 방식을 이어 갈지).

## 14. 내가 정한 것 (틀렸을 때 비용)

- **P1 본선만 · 연결로 제외:** 나들목 정체는 안 보인다. 다시 넣는 건 필터 한 줄.
- **P2 속도도 돌발과 같은 지연:** 화면이 더 늦어 보일 수 있다. 지연은 설정값이라 바꾸기 쉽다.
- **P3 스냅샷 3개 유지(대기 · 지금 · 바로 전):** 2MB 정도. 더 줄이려면 2개로.
- **P4 검증 기준(80%, 0속도 5%, createdDate):** 너무 빡빡하면 정상 데이터를 버린다. 처음 일주일 `collector_runs`의 거부 기록을 보고 조정한다.
- **P5 1차 표 정리 기간(7일 · 30일):** 3차 과거 재생을 하려면 늘려야 한다.
- **P6 SSE는 상태 스트림(로그 아님):** 재접속 시 놓친 중간값은 보내지 않는다. 지표는 지금 값만 중요해서다.
- **P7 `/insights` 주소와 탭 구성.**
- **P8 원활 ≥70 · 서행 40~70 · 정체 <40km/h:** ITS 일반 기준과 다를 수 있다. 숫자만 바꾸면 된다.
- **P9 도로 모양 파일을 저장소에 커밋:** 약 1~2MB 파일이 저장소에 들어간다. 노드링크 갱신 때만 바뀐다.
